# Hardware profile and blocking checklist

config/sensor_map.example.json schema_version=1 is a proposed inventory, not verified wiring. It contains 3 BMM350 + 3 LIS2DW12 components on three T1 tactile islands, 3 AS5600, 3 MPU6050, 1 BNO08X, and 2 ADG728 multiplexers. No sensor address, pin or mux channel is assumed, including addresses commonly used by a part family.

To approve a copied profile, a hardware owner must supply approved_by and wiring_reference plus a dated approval. Set approved=true only after review. Required bus records: named bus ID, MCU SDA/SCL GPIO, clock_hz, voltage, pullups and electrical reference. Sensor records require unique ID/type, bus, actual address, sample_rate_hz, output_format, timing behavior and initialization/electrical prerequisites. Confirm mux_required as true or false; where true, mux_path is an ordered list of verified mux ID/address/channel steps. Confirm each ADG728 bus/address and how it is connected. Check address conflicts, power sequencing, level compatibility, interrupt/data-ready wiring and any BNO08X reset/boot requirements.

Missing values are emitted by H01 as a checklist in logs/report. The supplied profile is copied into sensor_inventory.json to preserve exactly what was reviewed. No I2C probing or channel writes occur. The host's missing-value check is a prerequisite checklist, not a complete electrical validator. Even a complete map is rejected for physical acquisition until reviewed sensor drivers and an acquisition schema exist.

The JSON includes bus_record_template and mux_path_step_template as copyable record shapes. They are explanatory templates, not discovered buses or connections. Copy records into buses and the appropriate sensor mux_path only after verification. The number of actual buses remains unknown; do not interpret an empty buses list as proof of no buses.

Driver qualification must establish datasheet/register revisions, calibration policy (read-only persistent settings), sample format and units, start/end monotonic timestamps, bus error handling, initialization results, per-sensor deadlines, inter-sensor skew and payload bandwidth. Add driver unit tests with transaction fixtures, then validate actual reads on the assembly. Never substitute USB benchmark patterns for sensor readings. H01 simulation contains three illustrative timing sources and explicitly does not emulate the proposed 13-component assembly.
