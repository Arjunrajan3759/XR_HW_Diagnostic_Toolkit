# Portability and acceptance

The repository location is never hardcoded. PowerShell resolves its own parent; Python uses package-relative paths for shipped config and accepts an arbitrary evidence output path. Default output is relative to invocation working directory. CLI runs through the selected environment interpreter, scripts through the preserved .venv interpreter. PlatformIO is resolved through PATH or its standard per-user installation. No fixed COM port, camera serial, SDK directory or driver installation is assumed.

Serial enumeration is passive and dynamic. An operator-selected HELLO probe is needed to identify a diagnostic source without disturbing unrelated ports. Camera enumeration imports the wrapper and asks its API for devices/profiles. SDK import failure is separate from a missing device. Optional camera import never prevents protocol/analysis/simulation module import. Optional MCAP import fails only recording tests with a clear missing-module message; install requirements-recording for full simulation.

Pinned requirements target Windows AMD64 CPython 3.11. pyserial and the pytest runner are core; pyrealsense2 is camera; mcap/lz4/zstandard are recording; development adds Ruff and recording support for the complete suite. Do not copy .venv across machines. Minimal core install supports doctor, serial, H01/H02/H04 simulation and blocked physical runs; H03 simulation without recording uses the standard library. A clean environment without camera support must still pass missing-wrapper tests.

Clean-machine acceptance: clone into a path with spaces, install 3.11 x64, run setup -Recording -Dev without Camera, pip check, pytest, complete simulate, analyze and package. Then install Camera, run doctor with no devices and verify NOT_CONNECTED instead of an import crash. Build firmware with the pinned PlatformIO platform. On site, explicitly select devices, obtain any required firmware approval, run available physical tests and preserve all blockers. Ordinary tests must not request elevation or driver changes.

tests/test_integration.py relocates only xrdiag and config into a temporary directory with spaces and launches a subprocess from that new root with a relative output path. It checks source/config files for hardcoded user/SDK paths. Other tests mock COM enumeration and unavailable wrappers. This is automated relocation coverage, not proof of every possible clean Windows installation or driver stack.

Packaging includes only evidence file types and manifest-listed files, excluding build caches, hidden folders and default raw recordings. Textual home paths are redacted on export, while original evidence remains unchanged locally. Review shared evidence for unusual custom paths or personally supplied configuration strings; no heuristic redactor can recognize arbitrary secrets.
